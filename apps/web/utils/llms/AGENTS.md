**Parent context:** `../AGENTS.md`

## Purpose

The single gateway to language models. It picks the model for a user and use case, wraps the Vercel AI SDK calls with retries, fallbacks, prompt caching, sensitive-data policy, trial limits, and usage accounting. Feature code in `../ai/` goes through this folder and never builds a provider client itself. LLM rules are in root `AGENTS.md` and `.claude/skills/llm/SKILL.md`.

## For AI Agents

### Working In This Directory

- Model types are `default | economy | chat | nano | draft`. Deployments configure each as an ordered `provider:model` chain in env (`ECONOMY_LLMS`, `CHAT_LLMS`, `NANO_LLMS`, `DRAFT_LLMS`); the first entry is primary and the rest are fallbacks. The older `*_LLM_PROVIDER`/`*_LLM_MODEL` vars are deprecated and converted at startup.
- A user with their own `aiApiKey` gets that key and no fallback models; otherwise the deployment chain applies. Keep that split when touching `getModel`.
- Adding a provider means: a `Provider` constant, a `case` in `selectModel`, key lookup in `getProviderApiKey`, and env entries (see the environment-variables skill: `.env.example`, `env.ts`, `turbo.json`).
- Adding a use case means a new `LlmUseCase` key plus its model type in `LLM_USE_CASE_MODEL_TYPES`.
- `createGenerateObject` and friends expect `promptHardening` (defined in `../ai/security.ts`); do not bypass it for email-derived content.
- Provider and quota errors are classified in `../error.ts`; user-facing persistence goes through `../error-messages`. Add new classifiers there, not in feature code.
- Token usage is saved through `../usage.ts`. New call paths must still call `saveAiUsage`, or spend caps break.
- OpenAI user keys always set `store: false`; do not remove it.

### Testing Requirements

- Unit tests are co-located: `index.test.ts`, `fallback.test.ts`, `model.test.ts`, `retry.test.ts`, `use-cases.test.ts`, `model-usage-guard.test.ts`, `sensitive-content.test.ts`, and others. They mock `ai` with `vi.hoisted` mocks.
- Run from repo root: `pnpm test apps/web/utils/llms` or one file, e.g. `pnpm test apps/web/utils/llms/fallback.test.ts`.
- No live model calls here. Behavior evals are in `apps/web/__tests__/eval/` (`pnpm --filter inbox-zero-ai test-ai`).

### Common Patterns

```ts
const modelOptions = getModelForUseCase(emailAccount, LlmUseCase.DraftReply);
const generateObject = createGenerateObject({ emailAccount, label, modelOptions, promptHardening });
const result = await generateObject({ ...modelOptions, instructions, prompt, schema });
```

- Retry wrappers decide on error shape (`extractLLMErrorInfo`), not message text.
- Env-dependent behavior is read from `@/env` inside the function, so tests can override per case.
